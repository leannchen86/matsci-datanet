## 3. Changes needed

1. **"Desk, no approval" is not quite right.** The 40 + 10 scans and the Dara install live inside the user's own project folders. Using them means reading those folders and running that project's Python, read-only. The XRD session had that as a standing rule; this planning session was told not to open those folders at all. Say plainly: "needs your OK to READ (never change) your two project folders; outputs are written elsewhere." Also the replay scripts from C16 (sum_vs_real2.py, scan_headers.py) sit in a temporary area; rescuing them is on the needs-a-go-ahead list (late2).
2. **Read the Round 5 folder before writing a new protocol.** C16 says a dated protocol and metric files for a known-answer test on the same scans already exist (unverified). Writing a second, different dated protocol for the same data would muddy both. First step should be: read that one, then extend it.
3. **Separate "too hard" from "not in the library" from "marker fault".** In the user's set-up the same program drops from 38/40 (paper) to 32/40 at best. On new chemistries with the open library capped at 80 candidates, this will be worse. The protocol needs a per-scan flag "were all true ingredients in the candidate list?" and must report accuracy on flagged-yes scans separately. Without it the practice exam measures the library, not the difficulty.
4. **Fix the Stage 2 deliverable.** Only one program (Dara) is available locally; the other tool in the 38-vs-35 comparison is commercial. So "a verdict on whether the pooled sets can separate two tools" can only be arithmetic from the accuracy level and the count, not a real comparison. And by K4's own sizing (470-780 paired powders for a 5-point gap), a pool of about 240 plus a handful cannot do it. Reword the deliverable as: "Is it still too easy for Dara, by band?" Count separate powders (or ingredient pairs), not scans, as the unit for intervals: the 40 scans are 20 powders, and the 240 mixtures may be a few ingredient pairs at many ratios. This is the corpus's own method rule ("count clusters").
5. **Web-check before asking for any download (no download needed for this).** For each of the three sets record: do raw scans exist, are weighed answers given, licence, number of separate powders, file format, size. The files back "raw scans and answers public" for one of three only, and the build list says "if still available".
6. **Replay check: say what it decides, or drop the go / no-go.** K4 calls it "only to prove the pipeline runs" yet asks for "a written go / no-go". Two facts from C16 limit it: there are no short single-ingredient scans and 8 of 10 singles are on a shifted grid, so the 2-minute half of the set - where ALL of Dara's published errors sit (18/20 vs 20/20) - cannot be rebuilt faithfully. And K1 already re-marks the 40 real scans, which exercises the same marking pipeline. Either state a real question ("do summed scans get the same right/wrong verdict as the real 8-minute scans on at least N of 20?") or treat the replay as optional.
7. **Effort wording.** Replace "the files give no duration" with the corpus figure (B11: 3-12 months with a partner; about 10^3 expert-hours covers the multi-rater half) and mark "1-2 weeks for the practice exam" as the proposers' guess. Compute time for Stage 2 is unknown by two orders of magnitude.
8. **Missing approvals.** (a) Any install (readers for old instrument formats) or any fetch of reference structures for new chemistries is a download: needs a yes. (b) A contest-host account must be created by the user personally, and uploading a hidden answer key to a third-party host is outward-facing: needs a yes. (c) Count the Dara files first (40 / 41 / 60 / 61 / 70 in the notes).
9. **One-lab caveat in the lab request.** State that one lab, one instrument gives certain answers but a single-instrument exam; ask what a second instrument would cost rather than promising a field-wide ranking.
