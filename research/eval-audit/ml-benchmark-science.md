# ml-benchmark-science

## is eval work: mostly
EVAL: Almost all of it, and mostly META-evaluation (testing the tests, not the models). D1, N1, L1 = metric validity and versioning (is the scoring rule right and stable). D3, N2 = leakage and grouped splits. D4 = error bars and paired comparison. D6, N3, L2, L5 = test-set construction and hidden-test governance. N4 = ceilings (best achievable score). N5 = a benchmark-trust checklist. Inside D2, only the private check 'does a duplicate sit on both sides of my calibration/test split' is eval. The early project decision was explicit: 'evaluation data before a training corpus' (synth/storyline.md:63). So the user's instinct is right, and checking against eval principles first is a fair ask.
NOT: D0 file rescue = housekeeping. D5 and L3 (error notes to dataset owners) and L4 (neutral notice about 499 matching files) = data-error reporting and curation courtesy. N6 (flag-only suspect list) = data-quality tooling. Most of D2 = a data provenance audit: by the plan's own correction 12 (plan/plan.md:177) the 499 files carry no answer label, so they cannot inflate a test score. The critique of one company's 134-item test is an application of eval statistics, not a plan item. Honest framing for the user: every item before L2 audits existing exams. Only L2 creates new test data, and L2 needs a lab.
NAME: Meta-evaluation for materials ML on measured data: auditing how the exams are set, marked and sized, before trying to build a new one.
